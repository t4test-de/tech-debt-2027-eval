SUPPLEMENTARY MATERIAL
Obligation declarations for "What the Trace Graph Owes:
Traceability Debt as Unsatisfied Path Obligations"

This file contains the obligation sets evaluated in Section VII, written in the
declarative notation of Figure 1. They are published clause by clause so that a
disagreement about the reported numbers can be located in a declaration rather
than in a result.

Clause vocabulary (Table II):
  FROM       the population: artifact type and predicate
  TO         the admissible terminal artifact types
  VIA        admissible link sequences, one line per route; ? marks optional
  TARGET     an individual item or an aggregate
  DEPTH      the classification attribute and the per-class depth
  QUANTIFY   coverage (downstream) or justification (upstream)
  BASELINE   which baseline each hop is read in
  AGREE      attribute values that must agree along the path
  EXCEPT     the typed exception, its condition and its discharge duty
  DISCHARGE  existential, or joint with a side condition
  SOURCE     the clause or internal process item it derives from

Standard text is licensed and is not reproduced here. SOURCE names the clause.

1. AUTOMOTIVE  --  power window subject
===============================================================================

OBLIGATION sys_req_refined_to_sw
  FROM      SysRequirement
  TO        SwRequirement
  VIA       -
  VIA       ArchElement
  TARGET    individual
  QUANTIFY  coverage
  BASELINE  per hop, as released
  DISCHARGE existential
  SOURCE    "Automotive SPICE Guidelines 3.8.2.4"
  NOTE      Both routes discharge the obligation; supplying both is redundant.

OBLIGATION safety_req_verified
  FROM      Requirement[asil != QM]
  TO        TestCase
  VIA       ArchElement, UnitDesign
  TARGET    individual | group
  DEPTH     BY asil
  QUANTIFY  coverage
  AGREE     asil ALONG path
  EXCEPT    not_product_characteristic REQUIRES justification
  DISCHARGE existential
  SOURCE    "ASPICE 4.0 SWE.1, SWE.6; rating rule TAC.RL.1"

OBLIGATION asil_decomposition_complete
  FROM      Requirement[asil != QM]
  TO        Requirement
  VIA       allocation
  QUANTIFY  coverage
  DISCHARGE joint
            CARDINALITY all declared parts present
            CONDITION   children's asil recompose to the parent's
            CONDITION   targets declared independent
  EXCEPT    decomposition_declared REQUIRES annotation of the form X(Y)
                                   AND an independence record
  SOURCE    "ISO 26262-9:2018 cl. 5"

OBLIGATION element_assurance_agreement
  FROM      Requirement[asil != QM]
  TO        ArchElement
  VIA       allocation
  AGREE     asil BETWEEN requirement AND allocated element
  DISCHARGE existential
  SOURCE    "SWE-PR internal tailoring; ISO 26262-6"

OBLIGATION nothing_unauthorised_implemented
  FROM      SwRequirement
  TO        CustomerRequirement
  VIA       SysRequirement
  QUANTIFY  justification
  EXCEPT    derived REQUIRES justification
  DISCHARGE existential
  SOURCE    "customer supplier agreement"

3. MEDICAL  --  pulse oximeter subject
===============================================================================

OBLIGATION hazard_control_chain
  FROM      Hazard
  TO        VerificationRecord
  VIA       RiskControl, Requirement
  QUANTIFY  coverage
  DISCHARGE joint
            CARDINALITY every control named by the hazard
            CONDITION   each control resolves to an existing requirement
            CONDITION   each control resolves to an existing verification
  SOURCE    "IEC 62304 cl. 7.3.3; ISO 14971"
  NOTE      A field containing prose in place of identifiers does not resolve.
            Evaluation is over referents, not over non-emptiness.

OBLIGATION sw_req_traceable_to_a_source
  FROM      SwRequirement
  TO        SysRequirement | RiskControl | RegulatoryRequirement |
            UsabilityRequirement | InterfaceRequirement | OperationalConstraint
  QUANTIFY  justification
  DISCHARGE existential
  SOURCE    "IEC 62304 cl. 5.2.6"
  NOTE      The clause widens the admissible sources; it is not an exception.
            An unparented requirement still fails.

OBLIGATION class_graded_chain
  FROM      SwRequirement
  TO        TestCase
  VIA       ArchElement
  VIA       ArchElement, DetailedDesign
  DEPTH     BY softwareSafetyClass
            CLASS A  requirement -> test
            CLASS B  requirement -> architecture -> test
            CLASS C  requirement -> architecture -> detailed design -> test
  TARGET    individual | group
  QUANTIFY  coverage
  DISCHARGE existential
  SOURCE    "IEC 62304 cl. 5.3, 5.4, 7.3.3 (class-dependent applicability)"

===============================================================================
NOTES ON EVALUATION
===============================================================================

Link-pair evaluation, reported in Section VII as the comparison point, tests
only whether the FROM item carries a link of the terminal type directly. It
ignores VIA, TARGET, DEPTH, QUANTIFY, AGREE, EXCEPT and DISCHARGE.

Counts of artifacts, not of links, are reported throughout. An item whose
descendants carry the evidence is counted once.

Nesting: where an ancestor and its descendant both fail the same obligation,
repaying the descendant discharges the ancestor. Section VII reports both the
raw count and the count of independent repayment items.
